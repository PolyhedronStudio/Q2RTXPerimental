# Monster navigation performance and corner-traversal masterplan

Initial source audit: 2026-10-01; revised with corner-traversal analysis and implementation handoff on 2026-10-02; implementation outcomes updated through 2026-10-04. Baseline: branch `draw2d`, commit `63b55baa`, with existing local changes. This is an implementation plan with recorded correctness outcomes below, not a benchmark report. The original source review made no measured speedup, race-free execution or gameplay claim. Corner risks below are verified code paths and analytical counterexamples; the exact cause of the user-observed contact still requires a recorded runtime reproduction. Unrelated local changes are outside scope.

## Decision

Keep authoritative movement, collision, entity state and crowd admission on the 40 Hz game thread. Introduce one event-driven navigation worker for immutable-data path searches and geometric refinement, after fixing cache ownership and query reentrancy. Reuse the same solver synchronously as a reference and fallback mode. Do not continuously spin the worker or accelerate simulation time.

Establish safe corner traversal as a required correctness gate before offloading queries. First remove repeated work: lazy cache rebuilds, redundant face lookups, per-tick temporary allocations, duplicate searches and unnecessary crowd-wide scans. A worker can remove search work from the critical tick, but cannot eliminate physics, cover traces, crowd coordination, result validation or queue latency. Measure those separately before attributing a slow frame to A*.

Scope: compiled monster base/debug dummy, crowd/squad callers, cover selection, dynamic doors/walls, generation/load/clear/shutdown, debug queries and regression infrastructure. Separate build-time generation costs from recurring gameplay costs.

## Non-negotiable path and motion contracts

- Successful path output includes the exact requested start and goal in navigation feet space. If an endpoint is physically invalid, return a defined failure/partial status rather than silently moving it. Face recovery may select supporting topology without substituting endpoint coordinates.
- Separate route geometry, traversal constraints and cosmetic facing. A waypoint being near the monster does not prove the outgoing hull sweep is safe. A successful path query does not prove the realized movement followed it.
- Resolve one native hull description and conversion contract per request/update. Current trace radius is `(maxs.x - mins.x) / 2`; path code uses `max(abs(mins.xy), abs(maxs.xy))`. Explicitly reconcile non-square/asymmetric bounds; do not silently treat them as identical. Keep feet, bbox-origin and analytical-center coordinates named and typed/documented distinctly.
- Every completed route/result is revision-tagged; every accepted movement command is validated after all direction-changing contributions. Physics remains authoritative, but wall sliding in an unobstructed authored corner fixture is a failure signal, not success.
- A safe route may legitimately be impossible for a given hull. Return/wait/replan explicitly; never manufacture clearance by shrinking an LOS radius or accepting only part of a traversal probe.

## Memory and cache locality

A local vector normally places its small control object on the stack and its elements on the heap. Moving the object to file scope does not intrinsically improve locality. It retains capacity but introduces shared ownership and non-reentrancy. There is no measured large-stack-frame or stack-overflow finding here; obtain compiler stack reports for the actual call chain before changing storage for that reason.

Use three explicit ownership domains:

1. Published mesh snapshot: contiguous vertices, faces, adjacency, portals, static obstacle/corner data, room metadata and spatial index; immutable for readers. Split hot expansion fields from cold generation/debug fields only when profiles justify it.
2. Query context: one main-thread context and one worker context own A* nodes/heap, stamps, portal/corner scratch and refinement buffers. An in-flight resumable search must have exclusive context state. Do not allocate a full face-state array per monster.
3. Committed monster routes and bounded result slots: old routes survive pending replans; results transfer exclusive buffer ownership at a tick boundary. No pointers into scratch or containers another query may resize. Recycle released result buffers.

Retain capacity, reserve from measured high-water marks, and count growth events and retained bytes. Avoid worst-case reserves per monster. Budget snapshot bytes + still-live old snapshot bytes + context count Ã— context capacity + committed route capacities + bounded request/result storage. Use actual `sizeof`, capacities and allocator overhead, not assumed ABI sizes.

Benchmark packed immutable grids: sorted cell keys with `(offset,count)` ranges and a contiguous ID array, optionally indexed by a compact hash. Preserve exact cell identity, negative coordinates, deduplication and Z filtering. Average O(1) hash lookup does not make an entire multi-cell query O(1). Byte flags may simplify `vector<bool>` access, but must earn their larger footprint in measurement.

Use two retained buffers with alternating roles for refinement passes to reduce copies. Do not blindly swap a monster's route with shared scratch. Replace `nav_vector_t` with server-game standard-container aliases backed by the common zone allocator described below. Do not assume engine tag allocation/free is thread-safe.

### Server-game standard-container allocator: replace nav_vector_t

**Introduce one reusable server-game-only zone allocator family and `svg_*_t` standard-container aliases; migrate all `nav_vector_t` uses and remove that custom vector implementation.** Standard containers supply element lifetime handling and algorithms; the allocator supplies engine-tagged backing storage and accounting. No claim of an automatic speedup accompanies this architectural choice.

"Global to server game" means available throughout the server-game module, not a process-wide `operator new` override, new heap, or mutable singleton allocator. Add proposed headers `src/baseq2rtxp/svgame/memory/svg_zone_allocator.h` and `svg_containers.h`, with any non-template bridge in `svg_zone_allocator.cpp`. Keep them out of client/shared/engine public headers and exported ABI structs. Do not allocate through `gi` in static initialization before game imports exist, or destroy containers after those imports/module code become unavailable.

Use `svg_zone_allocator_t<T, Tag>` with compile-time `memtag_t Tag = TAG_SVGAME`. A rebind preserves Tag. All instances of the same allocator specialization are interchangeable if the implementation is stateless and uses the same engine domain; verify this before declaring `is_always_equal`. Different tags produce different allocator/container types and must not silently exchange ownership. Keep navigation explicitly under `TAG_SVGAME_NAVMESH`; choose level-lifetime tags only for owners destroyed before that tag is reclaimed. A common allocator implementation does not mean putting all memory under one tag.

### Allocator ownership and worker boundary (M5/M6)

`src/server/sv_game.cpp:1406,1818-1822` forwards allocation to `Z_TagMalloc` and free to `Z_Free`. `src/common/zone.cpp:251,386,417` changes shared `z_chain` and tag statistics without visible locking in those operations. Wrapping these functions in `svg_zone_allocator_t` does not make them thread-safe. Existing async generation must be audited too.

- [ ] Engine-tag allocation/free, including hidden container operations, occur only on the designated engine-safe owner or an audited exclusive engine phase. Add Debug thread-affinity checks at the server-game allocator boundary. A server-game-only lock cannot protect unrelated engine callers of the same zone metadata.
- [ ] Reserve worker `svg_vector_t` scratch/result buffers on the engine owner, then transfer exclusive access. Worker algorithm guards must check capacity BEFORE any append/resize that could grow; return the resource-limit status in release builds. Standard vector itself is not a bounded container. Avoid worker shrink/free/destruction and moves that deallocate replaced storage. Inner elements must not hide allocations/destructors reaching the zone allocator.
- [ ] Vector reserve does not solve worker use of node-based containers: map insertion and deque growth may allocate per operation, and unordered-map reserve preallocates buckets rather than all nodes. Prefer flat preallocated worker data; defer allocation to the owner. Any future worker arena/resource is an explicit, separately tested extension to the same accounting design, with no untracked heap fallback.
- [ ] Return completed/displaced buffers to their safe owner for recycling/destruction. Pin immutable snapshots until readers finish; do not allow last-reference destruction on an arbitrary worker to invoke tag freeing. Close submission and drain readers before destroying owners and calling `FreeTags`, unloading the level or unloading the DLL. `vector.clear()` retains backing memory and is NOT sufficient before bulk tag reclamation.
- [ ] If concurrent zone allocation becomes necessary later, synchronize the complete engine zone API and metadata readers, not just this adapter. Audit recursive `FreeTags`/`Z_Free`, reallocation, statistics and error/log callbacks. Keep this engine-wide change separate from the first navigation worker.

Gate: cancellation/result recycling and repeated map teardown show no double-free or stale owner; no forbidden worker allocation/free occurs under capacity stress; memory stays bounded; all migrated heap backing appears in tag/domain accounting. Only the container and allocator implementation strategy changes here; movement timing and worker publication/cancellation requirements below remain in force.

### M1: instrumentation and reproducible baseline

Measure high-resolution elapsed time for total server tick, navigation orchestration, start/goal lookup, global fallbacks, cache build, A*, portal/funnel construction, corner refinement, geometric LOS, movement traces, cover scoring/traces, crowd/squad work and debug drawing. Report p50/p95/p99/max, sample count and ticks exceeding 25 ms. Use thread CPU time where available to separate compute from waits. Separate generation/load/first query from warm gameplay.

#### M6.1 â€” slot state machine and enforceable limits

For the initial implementation, use preallocated slots plus short mutex/condition-variable coordination; do not require a custom lock-free queue. Each slot transitions `FREE -> QUEUED -> RUNNING -> READY -> FREE`. Only the owner thread creates/recycles buffers and pins/releases snapshots. The worker exclusively accesses payload while RUNNING and publishes immutable completion while holding the queue mutex. The owner reads READY only after taking the same mutex. Cancellation of RUNNING uses a separate atomic token checked by the worker; the owner must never recycle that slot until completion acknowledges cancellation. All waits use predicates and handle shutdown/spurious wakes.

The owner may replace a QUEUED request under the mutex. A new goal while RUNNING marks that request obsolete and occupies at most one separate latest QUEUED slot for the same entity. Bound pending replacements globally; a full pool records a coalesced retry intent in existing per-entity state rather than allocating an overflow queue. READY results consume slots until commit/discard; count them in saturation tests. Keep full solve and route commit outside the queue lock. Error paths publish a terminal status and return the slot through the same owner recycling path.

Start with one executing context and no suspended-context pool. Impose both hard work limits and a measured wall-time/cancellation quantum per request; overflow returns `resource_limited` with phase/reason. Never retry the same known-insufficient capacity at full rate. Owner-thread growth between jobs is permitted only within the configured memory ceiling. If supported fixtures require slicing to meet latency/fairness, add resumable state as an explicit follow-up before enabling the worker, retaining one exclusively owned context per suspended search and a measured cap. Do not label incomplete work `no_route`.

M1 measurements must produce a checked-in budget table before M6 acceptance: total slot count; maximum bytes per request/result; snapshot and old-snapshot peak bytes; context heap/face/portal/waypoint capacities; maximum work units and cancellation-check spacing per phase; completion count/time budget per tick; admission limits by priority. Derive capacities from measured high-water marks plus documented headroom and worst-case supported mesh size. Set a hard byte ceiling independently of slot count. Log every limit hit and retain the synchronous diagnostic mode for investigating unsupported cases. Numbers are deliberately not fabricated here; missing measured limits block worker default-enable.

Drain completion at the beginning of `SVG_RunFrame`, before entity thinking, and publish the tick's submissions at its end. Record actual placement relative to crowd updates and generation servicing. For stop/load/clear: close submission, mark cancellation, wake worker, acknowledge completion, join/drain readers, destroy/recycle tagged owners, then reclaim tags/collision data or unload. Avoid deadlock by never holding the queue mutex while joining; a worker must not wait for an owner callback during teardown. Restart only after the new snapshot and buffers are ready.
