## Result

Added a separate strict `Nav_TestSegmentClearance` reference API. Closed finite-segment XY distance includes both endpoints and stationary motion, and supplies minimum distance, nearest cached boundary edge, reason, mesh generation and topology revision. Stale/unprepared cache returns `cache_unavailable`; the query does not rebuild it. Zero-radius contact is blocked; positive required clearance permits equality. No arbitrary clearance-reducing epsilon is used.

The geometry helper is engine-independent and double precision. C1's K6 long-wall example has squared distance 100 versus required 256 and is correctly rejected by strict clearance. Tests also cover zero-length travel, reversed endpoints, subdivided walls, clear and exact-clearance controls, intersection/contact/overlap, a degenerate wall, and a small-angle crossing. These are analytical reproductions, not the user's recorded engine corner.

The existing permissive visibility API and gameplay callers are unchanged. The strict API is not yet connected to steering or route acceptance. This avoids silently changing visibility/recovery semantics before caller and native-hull audits. Boundary cache scanning is O(E), owner-thread only; snapshot/context ownership and indexed acceleration remain pending. Height filtering follows the existing step-height window and cannot establish native 3D hull clearance, containment or grounded support. Infinite reported clearance with no matching edges means only no cached boundary witness, not that off-mesh traversal is valid.
