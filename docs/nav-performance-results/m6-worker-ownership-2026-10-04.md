# M6 worker ownership and execution audit - 2026-10-04

Disposition: **M6 DONE**; source audit and [final runtime acceptance](m6-final-acceptance-2026-10-04.md) are complete. This service is explicitly activated for diagnostics. Actor scheduling and native result consumption remain M7 work.

## Worker call graph

`nav_worker_service_t::Run` waits on a standard condition variable with a predicate, selects a published fixed slot under the mutex, marks it RUNNING, and releases the mutex before `Nav_QueryFindPath`. The solver reads const copied graph spans, scalar policy, owned prior-membership bytes and one exclusive context. Its only execution controls are an atomic cancellation token and the standard monotonic clock. Heap operations, finite arithmetic, bounded predecessor reconstruction and reversal use prepared storage. No worker path calls `gi`, collision, entity callbacks, zone allocation/free, console output or snapshot pin/release. The old `Nav_ProcessPathQuerySliced` stub has no active callers and is not used by this service. Standard thread/condition-variable runtime machinery is outside the graph-buffer allocation assertion; no claim of process-wide allocation freedom is made.

Cancellation/work/deadline checkpoints include stale heap pops, every directed edge, stamp clearing, reconstruction and reversal. Work is checked on every checkpoint; cancellation/time are checked at entry and within 32 counted operations. Each heap operation is separately bounded by prepared capacity (at most 65,537 entries). Clock deadlines are cooperative, not absolute wall-time guarantees under OS preemption. Limit replies discard partial corridors and distinguish work, deadline, storage, expansion, edge-test and heap exhaustion from no route. A cancelled stamp rollover forces a complete clear on the next query before stamp one is reused. Each terminal reply owns copied counters, endpoints, full identity and graph corridor.

All buffer preparation and destruction occur on the designated owner. The instrumented standalone allocator asserts that graph allocations/frees never occur on the worker; warm submission assertions begin after caller request preparation, including MSVC debug proxies. Unknown virtual cost callbacks are not worker inputs. The service never invokes the native route function: funnel/refinement/LOS, semantic route records, floor support and physics remain in the audited M5 owner phase. Cancellation checkpoints for those owner operations do not belong to this worker entry.

## Slot and publication invariants

One worker and one executing context serve a fixed pool. Requests occupy FREE -> QUEUED -> RUNNING -> READY -> FREE slots. QUEUED replacement occurs under the mutex and retains its original queue age. RUNNING payload is immutable; replacement sets a separate atomic token and uses another queued slot. READY storage consumes capacity until the owner leases and releases it. A leased result cannot be recycled by a new submission. Slots do not contain actor pointers or callbacks.

The latest scalar identity table survives slot recycling, so an older ready reply cannot become current after a newer reply has already been consumed. Saturation advances the latest identity and leaves retry intent with the caller; no overflow queue is allocated. Priority aging and equal-priority group alternation operate over bounded slots. Urgent callers can explicitly publish; normal batches publish at tick end. An empty publication does not notify the worker. Stop closes submission and cancels under the mutex, then wakes and joins outside it. Running storage becomes owner-exclusive only after acknowledgement/join. No worker waits for an owner callback during teardown.

Short-lock telemetry measures owner acquisition wait/hold and worker selection/publication. Predicate scans and scheduler wake latency are not a complete OS lock profiler. No native commit or solve holds this mutex. The normal diagnostic consumer leases/releases at most two replies, checking a 500us deadline before each operation; a single owner operation can cross that cooperative budget. M7 must separately measure native preparation/commit.

## Snapshot and engine lifetime

The owner pins one copied snapshot before starting the reader. Stop joins and destroys transport buffers before releasing that pin. Retirement and identity overflow stop the reader before copied backing or the identity namespace can be reused. The implementation retains one snapshot object; it does not publish a second old/new copied generation concurrently. Supported retained service storage has independent 4MiB transport and 32MiB copied-snapshot ceilings (36MiB combined). These are retained reader budgets, not an engine-wide bound on live generation inputs or temporary owner snapshot construction.

`SVG_RunFrame` performs generation exclusion, bounded copied-input preparation, then graph completion consumption before level time advances, Lua callbacks and entity thinking. Batch publication follows entity/crowd/client/Lua/debug work and precedes generation servicing. Ordinary client callbacks drain the legacy borrowed-input generation only; they do not stop an independent copied-graph reader every tick.

Clear/load retire copied readers through owner cache invalidation; live mesh vectors may be cleared before that invalidation because the executing reader owns an independent deep copy and never reads live vectors. Submission/consumption cannot interleave this serialized owner operation. Regeneration invalidates the snapshot and joins before queuing its live-geometry writer. The API 1338 `DrainAsyncGeneration` export now combines query and generation drains for the engine map/collision lifetime barrier. Map command parsing calls it before BSP replacement. Module shutdown reaches `Nav_Clear` before navigation tags/entities/module code are freed; the engine unloads after the module shutdown returns. There is no new ABI export.

The existing collision model's thread-local/call-local state and generation barriers remain as documented in the M5 audit. This pure graph worker does not use collision from a background thread. Source ownership, instrumented contracts and native stress support these specific boundaries; they do not establish general race freedom or a sanitizer/race-detector pass.
